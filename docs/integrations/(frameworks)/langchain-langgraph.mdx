LangChain and LangGraph do not send traces to telemetry.dev by themselves. Add an OpenTelemetry instrumentation for LangChain, such as [OpenLLMetry](https://www.traceloop.com/docs/openllmetry/getting-started-python), and point its OTLP exporter at telemetry.dev. Chains, graph nodes, model calls, and tool steps then arrive as spans, and telemetry.dev computes cost from the token usage on model spans.

This guide uses OpenLLMetry. It was checked with `traceloop-sdk` 0.62.4, `langchain` 1.4.6, `langchain-openai` 1.7.2, and `langgraph`.

## Install

Use Python 3.10 or later. Install the packages in a virtual environment:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install traceloop-sdk langchain langchain-openai
```

You do not need a Traceloop account.

## Set the API key and exporter

Get a project API key from telemetry.dev. Then set the keys and the OpenLLMetry exporter configuration:

```sh
export TELEMETRY_DEV_API_KEY="td_live_..."
export OPENAI_API_KEY="your-openai-api-key"
export TRACELOOP_BASE_URL="https://ingest.telemetry.dev"
export TRACELOOP_HEADERS="Authorization=Bearer%20$TELEMETRY_DEV_API_KEY"
```

OpenLLMetry sends traces to `https://ingest.telemetry.dev/v1/traces`, and metrics to `/v1/metrics`. The `%20` is the space in `Bearer <key>`; header values in this variable are URL-encoded. Keep these keys out of version control.

## Trace a chain

This example sends one real request to OpenAI, so OpenAI charges apply. Save it as `first_trace.py`. Call `Traceloop.init()` before you build the chain:

```python first_trace.py
from traceloop.sdk import Traceloop
from traceloop.sdk.instruments import Instruments

Traceloop.init(
    app_name="langchain-first-trace",
    resource_attributes={"deployment.environment.name": "development"},
    instruments={Instruments.LANGCHAIN},
    disable_batch=True,
    telemetry_enabled=False,
)

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_messages([("human", "{question}")])
chain = prompt | ChatOpenAI(model="gpt-4o-mini", max_tokens=100)
response = chain.invoke(
    {"question": "What is OTLP?"},
    config={"run_name": "first-chain"},
)
print(response.content)
```

Run it:

```sh
python first_trace.py
```

The `Traceloop.init()` arguments do the following:

- `app_name` becomes the service name.
- `instruments={Instruments.LANGCHAIN}` turns on only the LangChain instrumentation. Leave it out to let OpenLLMetry instrument every library it supports.
- `disable_batch=True` sends each span as it ends, so a short script does not exit before its spans are sent. Leave it out in long-running apps.
- `telemetry_enabled=False` turns off OpenLLMetry's anonymous usage reporting to Traceloop. It does not change what your traces contain.

For other settings, see the [OpenLLMetry configuration guide](https://www.traceloop.com/docs/openllmetry/configuration).

## Trace a LangGraph graph

LangGraph runs on LangChain's callback system, so the same setup traces graphs. Initialize OpenLLMetry the same way, then build and run the graph:

```python
from typing import TypedDict

from langchain_openai import ChatOpenAI
from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    question: str
    answer: str


llm = ChatOpenAI(model="gpt-4o-mini")


def answer(state: State) -> dict:
    return {"answer": llm.invoke(state["question"]).content}


graph = StateGraph(State)
graph.add_node("answer", answer)
graph.add_edge(START, "answer")
graph.add_edge("answer", END)
print(graph.compile().invoke({"question": "What is OTLP?"}))
```

Install `langgraph` first with `python -m pip install langgraph`.

## Check the trace

Open your telemetry.dev project, select the `development` environment, and find the trace from `langchain-first-trace`. The chain example produces three spans:

| Span | What it is |
| --- | --- |
| `first-chain.workflow` | The chain run, with operation `invoke_agent` |
| `execute_task ChatPromptTemplate` | The prompt step |
| `ChatOpenAI.chat` | The model call, with model names, messages, finish reason, and token usage |

A graph run shows `LangGraph.workflow` and `invoke_agent LangGraph` spans, one `execute_task` span per node, and the model spans inside the nodes.

telemetry.dev computes cost for each model span from its token counts and the model's price. The workflow and task spans carry no token usage, so they add nothing to the trace's token or cost totals.

## Control captured content

By default, OpenLLMetry records prompts, completions, and chain inputs and outputs in span attributes. To stop recording them, set this variable before you start the app:

```sh
export TRACELOOP_TRACE_CONTENT=false
```

With content off, model spans keep token usage, model names, and other metadata. This is not a general redaction control: chain and tool names, model parameters, and any metadata your app attaches are still exported. To turn content back on for selected calls, see the [OpenLLMetry privacy guide](https://www.traceloop.com/docs/openllmetry/privacy/traces).

## Send from an existing OpenTelemetry setup

If your app already emits LangChain spans through the OpenTelemetry SDK, point its OTLP/HTTP exporter at telemetry.dev:

```sh
export OTEL_EXPORTER_OTLP_ENDPOINT="https://ingest.telemetry.dev"
export OTEL_EXPORTER_OTLP_PROTOCOL="http/protobuf"
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer%20$TELEMETRY_DEV_API_KEY"
export OTEL_SERVICE_NAME="your-service-name"
export OTEL_RESOURCE_ATTRIBUTES="deployment.environment.name=production"
```

These variables configure an exporter only. They do not install or start any LangChain instrumentation. For a new app, use the OpenLLMetry setup above.

## What telemetry.dev reads

telemetry.dev reads the OpenTelemetry GenAI attributes these instrumentations emit:

- Spans whose instrumentation scope name contains `langchain` are marked as LangChain spans.
- Token usage comes from `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`, or the older `gen_ai.usage.prompt_tokens` and `gen_ai.usage.completion_tokens`.
- The model comes from `gen_ai.request.model` and `gen_ai.response.model`, and the provider from `gen_ai.provider.name` or `gen_ai.system`.
- Messages come from `gen_ai.input.messages` and `gen_ai.output.messages`, the older indexed `gen_ai.prompt.*` and `gen_ai.completion.*` attributes, or `traceloop.entity.input` and `traceloop.entity.output`.

For the full list, see [span attributes](/reference/span-attributes).

## Troubleshooting

- **No trace appears.** Check that `TRACELOOP_HEADERS` contains your key and that `Traceloop.init()` runs before LangChain builds the chain. A short script without `disable_batch=True` can exit before its spans are sent.
- **The trace has no token usage or cost.** OpenLLMetry records usage only when the provider response includes it. Cost also needs a model that telemetry.dev has pricing for.
- **Using the telemetry.dev OpenAI wrapper instead.** Use OpenLLMetry for LangChain. In a test with `langchain-openai` 1.7.2, `instrument_openai()` from `telemetry-dev-openai` recorded each request but not the response or token usage of calls made through `ChatOpenAI`.

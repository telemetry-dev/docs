The Claude Platform can send OpenTelemetry traces of your Messages API requests and Managed Agents sessions to telemetry.dev. You add telemetry.dev as a destination in the Claude Console, and every request, model request, tool use, and agent turn arrives as a trace. No code changes are needed. This export is in beta at Anthropic.

## What it captures

- One span for each Messages API request, with a span for each model request, server tool, MCP tool, and compaction inside it
- Managed Agents sessions: each turn, model request, tool use, and outcome evaluation
- Model, response ID, stop reason, errors, and timing
- Input, output, cache-read, cache-write, and thinking token usage
- Prompts and responses, when the destination's content mode is **Full content**

## Get started

1. Create a telemetry.dev project API key. Keys use the `td_live_...` format.
2. In the Claude Console, open the organization's [OpenTelemetry settings](https://platform.claude.com/settings/telemetry-destinations) and click **Add destination**. You need the admin role.
3. Fill in the destination:

   | Field | Value |
   | --- | --- |
   | Provider | Custom |
   | OTLP endpoint URL | `https://ingest.telemetry.dev` |
   | Request headers | `authorization`: `Bearer td_live_...` |
   | Content mode | **Metadata only**, or **Full content** to include prompts and responses |
   | Workspaces | The workspaces to trace |

   Don't add `/v1/traces` to the endpoint URL. The Console adds it.

4. Click **Test** in the destination's **More actions** menu, then send a request. The destination shows **Healthy** within about a minute, and the trace appears in your project with the service name `claude-platform`.

## Token usage

Anthropic reports a request's usage on more than one span: on the request span and again on each model request inside it. telemetry.dev counts each request once, following [Anthropic's counting rule](https://platform.claude.com/docs/en/manage-claude/opentelemetry#count-tokens). Model request spans inside a Messages API request show no usage of their own, because the request span already carries it.

You can also export the Claude SDK's own spans to telemetry.dev with an OpenTelemetry exporter in your application. The SDK sends the trace context with each request, so the Console's span for that request becomes a child of the SDK span. When both arrive, telemetry.dev counts the Console's span, and the SDK span still appears in the trace. This needs the W3C trace context propagator registered in your application; see Anthropic's [trace context setup](https://platform.claude.com/docs/en/manage-claude/opentelemetry/api#connect-api-spans-to-your-own-traces). Without that link, both spans count. Claude Platform on AWS doesn't link them yet, so there, send the SDK spans and the Console destination to separate projects, or use one of the two.

## Good to know

- If your application already traces Anthropic calls with the [telemetry.dev Anthropic integration](/integrations/anthropic), those calls arrive twice and their usage counts twice. Send the Console destination to a separate project, or use one of the two.
- With **Full content**, prompts and responses go through your project's [capture and redaction settings](/platform/privacy) like any other telemetry.
- With **Full content**, set **Maximum content size in MB** under **Advanced settings** to 0.75 or lower. telemetry.dev rejects requests larger than 4 MiB, and Anthropic doesn't retry a rejected delivery.
- Anthropic delivers spans on a best-effort basis, so a span can occasionally be missing. telemetry.dev merges spans that arrive more than once.

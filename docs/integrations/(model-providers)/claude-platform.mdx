The Claude Platform can send OpenTelemetry traces of your Messages API requests and Managed Agents sessions to telemetry.dev. You add telemetry.dev as a destination in the Claude Console. Each request then arrives as a trace, with a span for each model request, tool use, and agent turn. No code changes are needed. Anthropic offers this export as a beta.

## What it captures

- One span for each Messages API request, with a span for each model request, server tool, MCP tool, and compaction inside it
- Managed Agents sessions: each turn, model request, tool use, and outcome evaluation
- Model, response ID, errors, and timing, with Anthropic's stop reason as the finish reason
- Input, output, cache-read, and cache-write token usage, and thinking tokens when Anthropic reports them. One-hour cache writes get the one-hour cache-write rate.
- Prompts, responses, tool results, and outcome evaluation explanations, when the destination's content mode is **Full content**

## Get started

1. Create a telemetry.dev project API key. Keys use the `td_live_...` format.
2. In the Claude Console, open the organization's [OpenTelemetry settings](https://platform.claude.com/settings/telemetry-destinations) and click **Add destination**. You need the admin role.
3. Fill in the destination:

   | Field | Value |
   | --- | --- |
   | Provider | Custom |
   | OTLP endpoint URL | `https://ingest.telemetry.dev` |
   | Request headers | `authorization`: `Bearer td_live_...` |
   | Content mode | **Metadata only**, or **Full content** to include prompts and responses |
   | Workspaces | The workspaces to trace |

   Don't add `/v1/traces` to the endpoint URL. The Console adds it.

4. Click **Test** in the destination's **More actions** menu, then send a request. The destination shows **Healthy** within about a minute, and the trace appears in your project with the service name `claude-platform`.

## Environment

Claude Platform spans have no deployment environment. telemetry.dev puts them in the environment of the API key. An environment-scoped key puts the spans in its environment, and an unscoped key puts them in the `default` environment.

To send workspaces to different environments, add one destination for each environment. Give each destination a key scoped to its environment.

## Token usage

Anthropic reports a request's usage on more than one span: on the API span for the request and again on each model request inside it. telemetry.dev counts each request once, following [Anthropic's counting rule](https://platform.claude.com/docs/en/manage-claude/opentelemetry#count-tokens). Model request spans inside a Messages API request show no usage of their own.

If you also export the [Claude SDK](/integrations/claude-sdk)'s own spans to telemetry.dev, the SDK span and the API span for a request carry the same usage. telemetry.dev counts the API span when it's a child of the SDK span, and the SDK span still appears in the trace. That link needs the W3C trace context propagator registered in your application; see Anthropic's [trace context setup](https://platform.claude.com/docs/en/manage-claude/opentelemetry/api#connect-api-spans-to-your-own-traces). Without the link, both spans count. [Claude Code](/integrations/claude-code#add-traces-beta) links its model request spans to API spans the same way.

## Good to know

- If your application already traces Anthropic calls with the [telemetry.dev Anthropic integration](/integrations/anthropic), those calls arrive twice and their usage counts twice. Send the Console destination to a separate project, or use one of the two.
- Claude Platform on AWS doesn't link SDK spans to API spans yet, so send them to separate projects or use one of the two.
- With **Full content**, prompts and responses go through your project's [capture and redaction settings](/platform/privacy) like any other telemetry.
- With **Full content**, set **Maximum content size in MB** under **Advanced settings** to 0.75 or lower. telemetry.dev rejects requests larger than 4 MiB, and Anthropic doesn't retry a rejected delivery.
- Anthropic delivers spans on a best-effort basis, so a span can occasionally be missing. telemetry.dev keeps one copy of a span that arrives more than once.
- The traces have the `claude` framework. telemetry.dev uses `anthropic.session.id` as the session, so one Managed Agents session groups all of its traces.
- When Anthropic shortens content, the span detail shows a "Truncated at source" badge.
- If the **Delivery** column shows `401`, the request header is incorrect or the key is revoked. A `403` means that the trace is already stored in a different environment. A `429` means that a free project used all of its ingestion quota, or that the project sent too many requests.

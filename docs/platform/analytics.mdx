The **Overview** page shows how a project is doing over a period: how many requests it served, how fast, how many failed, and what the model calls cost. It combines trace data with the OTLP metrics that your SDKs report.

Select **Overview** in the project sidebar. In telemetry.dev, a request is one trace.

## Choose a period

Select **Last 7 days**, **Last 30 days**, or **Last 90 days** in the date range. The default is 7 days. Select the refresh button to load new data.

The period cannot be longer than the project's retention. For example, a project with 14-day retention shows 14 days when you select **Last 30 days**, and the page says "Retention limits this view to 14 days."

## Read the summary cards

Each card shows a total for the period and a chart of the value over the period:

| Card | Value |
| --- | --- |
| **Requests** | Number of traces |
| **Error rate** | Traces with an error status, as a percentage of all traces |
| **p95 latency** | 95th percentile of trace duration |
| **LLM cost** | Total calculated model cost in USD |
| **LLM tokens** | Input tokens plus output tokens |
| **Active users** | Number of distinct user IDs in the traces |

The charts use hourly points for the 7-day period and daily points for longer periods. Select a card to open **Traces** for the same period; the **Error rate** card shows only traces with errors.

Each card except **Active users** compares the period with the period of the same length just before it. For **Error rate**, **p95 latency**, **LLM cost**, and **LLM tokens**, a decrease counts as an improvement.

A comparison appears only if the project's retention covers both periods. For example, the 30-day view needs at least 60 days of retention. With 14-day retention, the 7-day view has a comparison and the 30-day view does not.

## Break traces down by a dimension

The **Breakdown** table groups traces by **Model** at first. Select **Provider**, **User**, or **Operation** to change the grouping. Each row shows the group's **Requests**, **Error rate**, **p95**, **Tokens**, and **Cost**.

The table shows up to 6 groups, the ones with the most requests first. Select a row to list its traces, or its spans for a model, provider, or operation. The list opens with the period of the Overview. The rows of models and providers count only model calls, so their lists show only model calls too, with the **Operation: model calls** chip. Read [Find a trace or span](/platform/traces#find-a-trace-or-span).

## Read metric series

**Metric series** shows a small chart for each OTLP metric series that the project received in the period. The page shows the first two. Select **View all metrics (_n_)**, where _n_ is the number of series, to see the rest; if the list was cut short, the button reads **View top 100 metrics**.

telemetry.dev picks how to combine values from the metric type:

| Metric type | Value shown |
| --- | --- |
| Histogram with unit `s` or `ms` | p95 |
| Gauge | Average |
| Other types | Sum |

For a duration histogram, telemetry.dev estimates the p95 from the histogram's bucket bounds and counts.

The metric charts also use hourly points for the 7-day period and daily points for longer periods.

The page shows at most 100 series. If the project has more, it shows the series with the most data points and says that some series were omitted.

## When the page is empty

If the period has no traces and no metrics, the page shows **Go to Setup**. Select it to connect an application. Read [Connect an application](/platform/projects#connect-an-application).

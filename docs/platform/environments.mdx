An environment names the deployment that sent telemetry, such as `production`, `staging`, or `development`. Use environments to keep one project's deployments apart: you can filter by environment, limit an API key to one environment, and turn off prompt and response capture for one environment.

## Set the environment

telemetry.dev reads the environment from the OpenTelemetry resource attribute `deployment.environment.name`:

```bash
export OTEL_RESOURCE_ATTRIBUTES="deployment.environment.name=staging"
```

The telemetry.dev SDKs set this attribute from the `environment` option or the `TELEMETRY_DEV_ENVIRONMENT` variable. They use `production` when you set neither. Read [Configure `init()` in TypeScript](/sdk/typescript#configure-init) or [Configure `init()` in Python](/sdk/python#configure-init).

If `deployment.environment.name` is absent, telemetry.dev reads the older `deployment.environment` attribute. If both are absent, the telemetry gets the environment of its API key when the key is [limited to one environment](#limit-an-api-key-to-one-environment), and the environment `default` otherwise. This lets senders that cannot set resource attributes, such as the Claude API, still report an environment.

Set the same environment name on every service in a deployment. The dashboard shows names as sent, so `Production` and `production` appear as two filter values. Selecting either one in the **Traces** filter shows the telemetry of both. API key limits, capture settings, and alerts also treat them as one environment.

## Use environments in the dashboard

| Where | What you can do |
| --- | --- |
| **Traces** | Filter traces and spans by environment. The filter lists up to 100 environment names. The **Environment** column is hidden by default; turn it on in **Columns**. |
| **Sessions** | Filter sessions by environment. |
| Trace detail | Read the trace's environment on the **Metadata** tab. |
| **Logs** | Read a log's environment in the log details. |
| **API keys** | Limit a key to one environment. |
| **Settings** → **Privacy** | Turn prompt and response capture on or off for each environment. |

## The `experiment` environment

A prompt experiment records each item run as a trace in the `experiment` environment. Set this environment in the SDK client before you run an experiment of your code. Read [The experiment environment](/evals#the-experiment-environment).

The **Overview**, **Traces**, and **Sessions** pages leave out `experiment` by default. To see these traces, select `experiment` in the **Environment** filter of **Traces** or **Sessions**. Live evaluators with **Any environment** also leave it out.

## Limit an API key to one environment

Enter an **Environment** when you create a key. The key then accepts only telemetry with that environment and rejects other requests with `403 environment_mismatch`. Read [Limit a key to one environment](/platform/api-keys#limit-a-key-to-one-environment).

## Turn off capture for an environment

Open **Settings**, then select **Privacy** under the project in the settings sidebar. Under **Prompt capture**, turn off the switch in the environment's row. The change saves at once.

An environment that has no row of its own follows the project's **Capture by default** switch. The `production` and `development` rows are always present; select **Add environment** for other names. To cover telemetry that has no environment attribute and uses a key without an environment, add a row named `default`.

Read [Turn off prompt and response capture for an environment](/platform/privacy#turn-off-prompt-and-response-capture-for-an-environment) for what this setting removes and what it keeps.

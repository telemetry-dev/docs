A project holds the telemetry for one application, with its own API keys, privacy settings, and retention. Projects belong to an organization, which holds members, billing, and usage. Use [environments](/platform/environments) inside one project to separate production from staging.

## Sign in and get an organization

Sign in with an email address and a password. **Continue with GitHub** and **Continue with Google** appear when the deployment has those providers set up.

After you verify your email address, telemetry.dev creates an organization named after you, such as `Ada's workspace`, and makes you its owner.

If an invitation for your email address is waiting, telemetry.dev does not create that organization. It opens onboarding instead. There you can **Accept** or **Decline** each invitation, or select **Create an organization**.

To add another organization later, open the organization switcher in the sidebar and select **New organization**. You can own up to 5 organizations.

## Create a project

Any member of the organization can create a project.

<Steps>
  <Step title="Open the project list">
    Select **All projects** in the sidebar.
  </Step>
  <Step title="Name the project">
    Select **Create project**. Enter a **Project name** of 1 to 100 characters, then select **Create project**.
  </Step>
  <Step title="Connect an application">
    telemetry.dev opens the project's **Setup** page, where you create the project's first API key. Read [Connect an application](#connect-an-application).
  </Step>
</Steps>

Each plan limits the number of projects in an organization:

| Plan | Projects |
| --- | ---: |
| Free | 1 |
| Pro | 5 |
| Team | Unlimited |

At the limit, the project list shows **Upgrade to add projects** instead of **Create project**. It opens the organization's **Billing** settings. Read [Plans and billing](/platform/billing#compare-plans).

## Connect an application

Select **Setup** in the project sidebar. The page is a checklist titled **Send your first trace**:

1. **Choose what to trace.** Select your integration. You can search by name or filter by language. Integrations are grouped as **Model providers**, **Frameworks**, **Coding agents**, and **SDKs and OpenTelemetry**.
2. **Create an API key.** Select **Create API key**, or use a key you already have. Creating a key needs the owner or admin role. The new key goes into the code blocks of the next steps. You see it only once.
3. Follow the integration's own steps, such as installing a package and wrapping your client.
4. The last step waits for data. When the first trace arrives, the page shows it with **Open trace**.

Where a code block sets `OTEL_SERVICE_NAME`, it uses the project name in lowercase with dashes. For the full instructions of each integration, read its guide under [Integrations](/integrations).

## Rename or delete a project

An organization owner or admin can rename or delete a project.

Select **Settings** in the project sidebar to open the project's **General** settings. Change **Project name** and select **Save**, or select **Delete project** under **Danger zone** and confirm.

Deleting a project removes the project and its API keys, so the keys stop working at once. It also deletes the project's stored telemetry. You cannot undo it.

## Rename the organization

An organization owner or admin can rename the organization. Open the organization switcher and select **Organization settings** to open the organization's **General** settings. Change **Organization name** and select **Save**.

Only an owner can delete the organization. **Delete organization**, under **Danger zone** on the same page, removes every project in it and all of their telemetry.
